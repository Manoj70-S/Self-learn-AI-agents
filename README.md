# CogniMem: Self-Evolving Long-Term Memory Layer for AI Agents

**CogniMem** is a cognitive long-term memory architecture designed from first principles for autonomous agents and LLM applications. It provides dynamic user-preference persistence, atomic fact extraction, contradiction resolution, and context-aware retrieval across independent conversational sessions.

---

## 1. Why Naive RAG & Raw Chat History Fail

| Challenge | Raw Chat History / Sliding Window | Naive Chunk RAG | CogniMem Cognitive Layer |
| :--- | :--- | :--- | :--- |
| **Context Window** | Explodes tokens, high latency & cost | Fast, but retrieves fragmented chunks | Injects only compact, high-scoring atomic facts |
| **Cross-Session Persistence** | Lost completely when session ends | Kept, but cannot track personal traits | Scoped strictly to `user_id` and persistent |
| **Contradictions** | Confused by conflicting dialogue turns | Retrieves both *"Lives in Amsterdam"* and *"Moved to Berlin"* | **Reconciliation Engine**: detects conflicts, invalidates older facts, and marks them `SUPERSEDED` |
| **Redundancy** | Re-sends duplicate chatter | Accumulates duplicate vector chunks | **Deduplication Engine**: flags identical statements as `NOOP` |
| **Time Awareness** | Static | Oblivious to temporal recency | **Exponential Recency Decay** prioritizes recent updates |

## 2. Architecture & Cognitive Pipeline

```
 [User Conversation Turn]
            │
            ▼
 ┌──────────────────────┐
 │  CognitiveExtractor  │  ◄── Analyzes dialogue turns; extracts normalized
 │ (LLM / Rule Fallback)│      atomic statements & categorical metadata
 └──────────┬───────────┘
            │ Candidate Fact: "User lives in Berlin" [category: location]
            ▼
 ┌──────────────────────┐
 │   MemoryReconciler   │  ◄── Searches vector store for existing user memories.
 │ (Conflict Resolution)│      Performs hybrid categorical & semantic matching.
 └──────────┬───────────┘
            ├── [Identical Content]      ──► NOOP (Ignore to prevent bloat)
            ├── [New Information]        ──► ADD (Insert novel MemoryItem)
            └── [Contradicts Old Memory] ──► UPDATE (Mark old memory SUPERSEDED,
                                                     insert new MemoryItem)
            │
            ▼
 ┌──────────────────────┐
 │  Vector Storage Core │
 │ (SQLite / Qdrant)    │  ◄── Stores payload, embeddings, status, timestamps,
 └──────────┬───────────┘      access counts, and provenance pointers.
            │
            ▼
 ┌──────────────────────┐
 │ Context-Aware Search │  ◄── Composite Score = (1 - w) * Similarity + w * RecencyDecay
 └──────────┬───────────┘
            │ Injects into Agent Prompt
            ▼
 [Personalized Response Tailored to Long-Term Memory]
```

## 3. Mathematical Foundations

### A. Cosine Semantic Similarity
Dense representations generated by embedding models (e.g. `text-embedding-3-small` or offline deterministic projections) are compared via cosine angle:
$$\text{Similarity}(u, v) = \frac{u \cdot v}{\|u\|_2 \, \|v\|_2}$$

### B. Exponential Recency Decay
Human memory naturally prioritizes fresh observations over stale facts. CogniMem applies an exponential decay curve with a configured half-life (default 30 days):
$$\text{RecencyFactor}(\Delta t) = e^{-\lambda \cdot \Delta t}$$
where $\Delta t$ is elapsed time in days and $\lambda = \frac{\ln(2)}{t_{1/2}} \approx 0.023$.

The final retrieval score is a weighted blend:
$$\text{Score} = (1 - w_{\text{recency}}) \cdot \text{Similarity} + w_{\text{recency}} \cdot \text{RecencyFactor}$$

## 5. Quickstart & Verification

### Step 1: Launch the Interactive Web Dashboard
```bash
streamlit run app.py
```
*Provides a visual UI with Live Chat, Memory Audit Inspector, Knowledge Graph, and Persona Card.*

### Step 2: Run the FastAPI REST API Server
```bash
uvicorn server:app --reload
```
*API docs available at `http://localhost:8000/docs`.*

### Step 3: Run the Multi-Session CLI Demo
```bash
python demo.py
```

### Step 4: Run the Unit Test Suite
```bash
python -m pytest tests/test_memory.py -v
```

### Step 5: Enable OpenAI & Qdrant Cloud (Optional for Production Scale)
1. Copy `.env.example` to `.env` and configure your API key:
   ```ini
   OPENAI_API_KEY=sk-...
   COGNIMEM_STORAGE_PROVIDER=qdrant  # or 'sqlite'
   ```
2. If using Qdrant, spin up the local container:
   ```bash
   docker-compose up -d
   ```

## 6. Code Usage Example

```python
from cognimem import CogniMemory, CognitiveAgent

# Initialize memory with SQLite persistence
memory = CogniMemory(db_path="user_memory.db")
agent = CognitiveAgent(memory=memory)

USER_ID = "alex_engineer"

# Session 1: Onboarding
agent.chat(
    user_message="I'm Alex. I live in Amsterdam and prefer FastAPI and PostgreSQL.",
    user_id=USER_ID
)

# Session 2: Days later (Empty short-term buffer)
response = agent.chat(
    user_message="What stack should I use for my new microservice?",
    user_id=USER_ID
)
print(response["reply"])
# Agent automatically recalls Alex's preference for FastAPI and PostgreSQL!

# Session 3: Preference update (Conflict Resolution)
agent.chat(
    user_message="I just moved to Berlin.",
    user_id=USER_ID
)

# Verify profile: "Lives in Amsterdam" is superseded; "Lives in Berlin" is active!
profile = memory.get_profile(USER_ID)
print(profile)
```
