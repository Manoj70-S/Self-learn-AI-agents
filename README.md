# CogniMem: Terminal-Native Cognitive Long-Term Memory for AI Agents

**CogniMem** is a cognitive long-term memory architecture designed from first principles for autonomous agents and LLM applications. It operates **100% in the terminal**—no web servers, no bloated browser dependencies, and zero unnecessary overhead.

It provides dynamic user-preference persistence, atomic fact extraction, contradiction resolution, knowledge graph relations, and Stanford ACT-R cognitive retrieval across independent conversational sessions.

---

## 1. Why Naive RAG & Raw Chat History Fail

| Challenge | Raw Chat History / Sliding Window | Naive Chunk RAG | CogniMem Cognitive Layer |
| :--- | :--- | :--- | :--- |
| **Context Window** | Explodes tokens, high latency & cost | Fast, but retrieves fragmented chunks | Injects only compact, high-scoring atomic facts |
| **Cross-Session Persistence** | Lost completely when session ends | Kept, but cannot track personal traits | Scoped strictly to `user_id` and persistent |
| **Contradictions** | Confused by conflicting dialogue turns | Retrieves both *"Lives in Amsterdam"* and *"Moved to Berlin"* | **Reconciliation Engine**: detects conflicts, invalidates older facts, and marks them `SUPERSEDED` |
| **Redundancy** | Re-sends duplicate chatter | Accumulates duplicate vector chunks | **Deduplication Engine**: flags identical statements as `NOOP` |
| **Time Awareness** | Static | Oblivious to temporal recency | **Exponential Recency Decay** prioritizes recent updates |
| **Entity Connections** | None (Isolated text snippets) | None | **Relational Knowledge Graph**: Extracts `(Subject, Predicate, Object)` triples |

            │ Injects into Agent Prompt
            ▼

## 3. Mathematical Foundations: Stanford ACT-R Cognitive Scoring

CogniMem does not rely solely on raw vector cosine similarity. High-similarity trivial comments must never drown out critical constraints (e.g., life-threatening medical allergies or core identity traits).

Retrieval computes an activation score based on four cognitive dimensions:

### A. Cosine Semantic Similarity
Dense representations generated by embedding models (e.g. `text-embedding-3-small` or offline deterministic projections) are compared via cosine angle:
$$\text{Similarity}(u, v) = \frac{u \cdot v}{\|u\|_2 \, \|v\|_2}$$

### B. Exponential Recency Decay
Models forgetting curves with a configurable half-life (default 30 days):
$$\text{RecencyFactor}(\Delta t) = e^{-\lambda \cdot \Delta t}, \quad \lambda = \frac{\ln(2)}{t_{1/2}} \approx 0.023$$

### C. Intrinsic Importance
Assigned at extraction time on a scale from $0.0$ (trivial chit-chat) to $1.0$ (critical constraints, non-negotiable tech requirements, dietary allergies).

### D. Access Frequency Factor
Frequently recalled memories are strengthened over time:
$$\text{FrequencyFactor}(n) = \min\left(1.0, \frac{n + 1}{10}\right)$$

### Composite Activation Formula
$$\text{Activation Score} = w_{\text{sim}} \cdot \text{Similarity} + w_{\text{rec}} \cdot \text{RecencyFactor} + w_{\text{imp}} \cdot \text{Importance} + w_{\text{freq}} \cdot \text{FrequencyFactor}$$

## 5. Terminal CLI Usage & Quickstart

The application runs directly in your terminal with zero web dependencies.

### Interactive REPL Chat
```bash
python cli.py
# or specify user:
python cli.py chat --user alex_engineer
```

Inside the interactive REPL, use slash commands to inspect memory:
- `/memories` - Show active facts and superseded conflict audit trail
- `/graph` - Display Knowledge Graph entity-relation triples
- `/persona` - Print the synthesized executive Persona Card
- `/search <query>` - Run ACT-R cognitive multi-factor semantic search
- `/switch <user_id>` - Switch active user in multi-tenant mode
- `/reset` - Purge memories for the active user
- `/exit` - Close the session

### Non-Interactive CLI Subcommands

```bash
# List all active and superseded memories
python cli.py memories --user alex_engineer

# Inspect Knowledge Graph triples
python cli.py graph --user alex_engineer

# View synthesized Persona Card
python cli.py persona --user alex_engineer

# Run ACT-R cognitive multi-factor search
python cli.py search "FastAPI" --user alex_engineer

# Directly add a fact into memory
python cli.py add "Alex prefers dark roast coffee." --user alex_engineer

# Reset memories for a user
python cli.py reset --user alex_engineer
```

## 7. Storage Options: SQLite or Qdrant Cloud

CogniMem supports both local zero-configuration SQLite and enterprise Qdrant Cloud:

### Option A: Local SQLite (Default, Zero Setup)
Runs out of the box with `cognimem.db`. No containers or cloud keys required.

### Option B: Qdrant Cloud / Container
Set environment variables in `.env`:
```ini
COGNIMEM_STORAGE_PROVIDER=qdrant
QDRANT_URL=https://your-cluster-id.aws.cloud.qdrant.io
QDRANT_API_KEY=your-api-key
QDRANT_COLLECTION=agent_memories
```
Run with `--storage qdrant`:
```bash
python cli.py --storage qdrant chat --user alex_engineer
```

## 8. Python SDK Code Example

```python
from cognimem import CogniMemory, CognitiveAgent

# Initialize memory (defaults to SQLite persistence)
memory = CogniMemory(db_path="user_memory.db")
agent = CognitiveAgent(memory=memory)

USER_ID = "alex_engineer"

# Session 1: Onboarding
agent.chat(
    user_message="I'm Alex. I live in Amsterdam and prefer FastAPI and PostgreSQL.",
    user_id=USER_ID
)

# Session 2: Days later (Empty short-term buffer)
response = agent.chat(
    user_message="What stack should I use for my new microservice?",
    user_id=USER_ID
)
print(response["reply"])
# Agent automatically recalls Alex's preference for FastAPI and PostgreSQL!

# Session 3: Preference update (Conflict Resolution)
agent.chat(
    user_message="I just moved to Berlin.",
    user_id=USER_ID
)

# Verify profile: "Lives in Amsterdam" is superseded; "Lives in Berlin" is active!
profile = memory.get_profile(USER_ID)
print(profile)
```
